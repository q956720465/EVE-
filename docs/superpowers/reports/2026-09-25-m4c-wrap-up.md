## 5. 实施期间的关键裁决（账本 Ruling 摘要）

1. **FIFO 口径 = 剩余持仓成本**（买 100@10 + 100@20，卖 100 后成本是 **20** 不是 15）：15 会少报成本 → 漏报真实亏损，方向错。
2. **ESI 契约与计划假设不符（T7 实测）**：`/wallet/transactions/` 无日期型 `since`（只有 `from_id`）、`/wallet/journal/` 只有 `page` 且**只回溯 30 天** → 改本地水位过滤 + URL 恒定（保住 `Expires`/304）。
3. **钉钉错误码常量被实测推翻（T10）**：`300001` = "token is not exist"（限流是 `130101`/`410100`）；`400013` = 群解散；**钉钉报错也返回 HTTP 200**，成败只能读 body 的 `errcode`。
4. **插入 T12B（令牌刷新）**：access token 约 20 分钟过期而 `is_expired` 无人消费 → 不做则整条链路 20 分钟后静默停更。
5. **T14 追加 GUI 登录入口 + 采集线程令牌接线**：计划 brief 漏了登录命令，而 app 原为 `SchedulerConfig::default()`（char 侧关闭、无令牌）→ 登录成功也不同步。
6. **回调端口从 `redirect_uri` 派生**：端口无独立 env 键，把回调解到别的端口会 bind 错端口 → 浏览器落空 → 白等 180 s；`redirect_uri` 是权威（EVE 精确匹配）。
7. **【全分支评审】守护进程 `serve`/`round` 从未带上角色配置**（`main.rs:633` 用了 `..Default::default()`）→ 无人值守进程里角色永不同步、告警永不产生，且无日志无报错。这是**逐 Task 评审看不见、只有整分支评审能看见**的集成缺陷，也是本里程碑最重要的一条整改。

## 6. 已知缺陷与欠账（真实存在，未修）

1. **形态 ③ 排除买方中介费**（`char_orders` 无 `volume_total`，需迁移 v7）：方向是**可能漏报小额亏损**；卡片已明说"买入侧中介费本机无法归属，未计"。
2. **journal 只回溯 30 天**（ESI 硬限制）：首启回填窗之外的已实现成本只能标"成本未知"。
3. **`prune_alerts_cleared` 无生产调用者** → `alerts` 表实际无界；`alerts_list` 每次全表读取。
4. **调度器层令牌刷新无测试接缝**（所有 scheduler 测试种 `expires_at: i64::MAX`）：删掉刷新块不会有测试失败。收口办法已写明 —— 给 `SchedulerConfig` 加一个默认 `DEFAULT_TOKEN_ENDPOINT` 的字段，让 scheduler 测试能指向本地桩。
5. **保存设置会把"生效值"写进库**：清空即回落环境变量，但一旦保存过，此后改 `EMD_CHAR_CLIENT_ID` 不再生效（UI 显示的就是生效值，可发现性瑕疵而非正确性问题）。
6. **②（挂买单套牢）在某站点没有对应簿行时静默消失**（站点不在聚合星域，或被薄/批发/陈旧闸门滤掉）：无计数、无 warn、回合报告里也看不到 → 用户看到"零告警"却无从判断原因。方向为漏报。建议在 `AlertRoundReport` 加 `skipped_no_book`。
7. **`journal_entries` 是 at-most-once**：某些失败顺序下本轮已取回的流水会永久丢失。
8. **T14 的 UI 层欠账**：载入失败与载入中同形（面板永远显示「读取中…」）；fixture 告警时间戳冻在模块加载时刻；多角色切换后告警行无归属标注；通道标签是二分猜测（"钉钉" vs "本地"）。
