# M4c 实施经验总结（外部协议 · 集成缺陷 · 静默零 · 验证法）

> 来源：M4c（EVE SSO 角色挂链 + 亏损告警 + 钉钉推送）34 个提交、15 个 Task 的 subagent-driven 实施 + 全分支评审。配套收官报告：`2026-09-25-m4c-wrap-up.md`。这份文档只留**可迁移的经验**，不重复交付内容。

---

## 1. 外部协议常量：计划里的值默认当"待核"，且要真打一次

**事实（钉钉）**：计划里写的钉钉错误码含义**基本全错** —— `300001` 实际是 "token is not exist"（不是限流；限流是 `130101`/`410100`），`400013` 是群解散，机器人停用是 `400102`。更关键的是**钉钉报错也返回 HTTP 200**，成败只能读 body 的 `errcode`；只看 HTTP 状态码会把"密钥错/被停用"全都当成成功。

**事实（ESI）**：计划假设 `/wallet/transactions/` 支持日期型 `since`、`/wallet/journal/` 可按日期增量 —— 实测都不成立（前者只有 `from_id`，后者只有 `page` 且**只回溯 30 天**）。若不实测，"增量"要么退化成全量重拉、要么静默漏数据。

**做法**：
- 每个外部常量分三类标注：**实测过的**（记日期 + 出处）、**官方文档确认的**、**待核**。计划里标了"待核"的反而安全，没标的更容易被当事实写死。
- 有网络就把"平台返回码表"当假设去证伪（发一次未加签/加签请求、对照官方错误表）。
- 把错误码映射做成**单一常量块 + 同时吃 code 与 errmsg**（同一 code 的不同 errmsg 语义可能不同，比如 `300001`/`300005`）。

## 2. 集成缺陷只在"整分支"尺度可见 —— 逐任务评审的盲区

**实例**：M4c 的 14 个任务各自评审全绿，但收尾的全分支评审抓出一个 Critical：`emd serve`/`emd round` 构造 `SchedulerConfig` 时用了 `..Default::default()`，而 `CharConfig::default()` 的开关是**关**的 → 无人值守的守护进程里角色永不同步、告警永不产生，**无日志、无报错、无提示**，而同一份代码的 GUI 入口是对的。

**根因不是"某个任务写错"**，而是**同一条硬约束要在多个入口各带一次**：GUI 有 1 个构造点（对），daemon 有 4 个（其中 2 个漏）。

**做法（可直接复用）**：
- 收尾评审做"**契约 × 入口**"矩阵：把该契约的**全部构造点/调用点**列出来（用 grep 列，不靠记忆），逐个比对。
- 派发任务时，把"每个入口都要带 X"升级成"**列出全部构造点并逐个处理**"——前者会被理解成"我改的这个入口带上就行"。
- 有一条规则就该有一个 grep 级检查脚本或一条测试（本例可加"任何 `SchedulerConfig {` 都必须显式带 `char:`"的结构测试）。

## 3. "静默零"清单：宁可选错，也不要静默返回空

本里程碑撞到 4 种"返回空集合而不报错"，全部是**用户看不出来**的失效：

| 形态 | 机理 | 对策 |
|---|---|---|
| SQLite 跨存储类比较 | `alert_key TEXT = order_id INTEGER` 恒为空，**不报错** | 规范文本形态（`order:{id}`/`tx:{id}`）只由一处构造；写一条**真表 SQL 演示**测试证明裸比较返回 0 行 |
| 缺簿行 | 某站点没有聚合簿 → 某类判定静默消失，无计数无 warn | 在回合报告里加 `skipped_no_book` 计数（已挂账） |
| at-most-once 拉取 | 水位在**拉取时**推进，若后续步骤失败，本轮已取回的数据永久丢失 | 消费放到任何可失败步骤**之前**，并在注释写明"错过即永久丢失" |
| 保守分支写成无条件 | "售空就永久标 Unknown" 让高换手类型全静默失效 | 保守分支要问"这是终态还是瞬时态"；终态才保守 |

**判定法**：对每个"返回空 / `None` / 跳过"的分支问一句 —— **用户能否区分"真的没有"与"没跑"？** 分不出就得有计数、日志或状态字段。

## 4. 测试要同时钉"纯函数"和"调用点"

纯函数全绿 ≠ 功能可用。本例中"调度器真的会刷新过期令牌"这条**接线**没有任何测试能失败：所有调度器测试都种 `expires_at = i64::MAX`（永不过期），删掉刷新块测试照样全绿 —— 而那正是这个功能存在的理由。

**对策（按成本从低到高）**：
1. **接缝**：给配置结构加一个默认指向真实端点的字段，让测试能把它指向本地桩（最彻底）。
2. **透传测试**：把构造逻辑抽成纯函数并断言"传进去什么就带出来什么"，同时在报告里**如实写明"调用点由评审保证、不由测试保证"**。
3. 至少要有**一个**能因"接线断了"而失败的测试，否则该功能处于"无人看守"状态。

**env 类全局态的注意**：同一测试二进制里"改环境变量"与"拿环境变量快照当基准"的测试会**并行互相污染**（偶发翻转）。用一把只给这类测试用的互斥锁，或干脆不写依赖 env 的测试。

## 5. 凭据与泄漏：哨兵测试的写法与掩码的结构化

- **哨兵测试要双向**：先**正向**断言"凭据确实被消费了"（输出里有角色名/过期时间/水位），**再**断言负向（不含 `AT`/`RT`/`eyJ`/`Bearer` 字样）。只做负向断言时，流程压根没跑到也会"通过"。
- **掩码要结构化，不靠自觉**：手写 `Debug`（不 `derive`，否则 `{:?}` 打印活令牌）；错误串**绝不取第三方库的 `Display`**（reqwest 会附 `for url (...)`，而 URL 里就带着 webhook token）；给 UI 的只有 `secret_set: bool`，不给明文也不给掩码残片。
- **三态编辑要在类型上可表达**：`None`=不改、`Some("")`=显式清空、`Some(s)`=设置。把"空串"当"未修改"会**静默关掉签名** → 平台报错 → 还把用户引去怪机器人。UI 侧"输入框留空"必须映射成"不改"。
- **配置读回的边界**：打码值（含 `***`）必须被拒绝入库，否则库里躺着一条假密钥，之后每次都失败且看不出毛病。
- **独立复算**：签名/摘要类常量一定要用第二条实现（openssl / python）复算一遍。自证常量挡不住 key/msg 写反 —— 那种错会**稳定地错**，只回一句笼统错误码。

## 6. 口径歧义：按"错的方向"裁定，而不是按"哪个更常见"

- **FIFO 均价**：剩余持仓成本（买 100@10 + 100@20、卖 100 后 = **20**）vs 全窗加权（15）。选 20 的理由不是常见，而是 **15 会少报成本 → 漏报真实亏损**，而整个功能就是为防亏损。
- **费率税基**：卖出**全额**，不是利润。
- **方法论**：两种读法都说得通时，先问"哪种会把风险方向搞反"，再选；并把口径写进模块头 + 用锚点数字钉死（`ask=100/bid=110/8% → 期望值`）。

## 7. 平台/工具链小坑（Windows 桌面客户端）

- `cmd /C start "" <URL>`：URL 里的裸 `&` 会被 cmd 截断（`Command` 只对含空格的参数加引号）→ 浏览器打开残 URL、用户白等超时。必须 `raw_arg` + 显式加引号 + `CREATE_NO_WINDOW`；且普通 `.arg("\"{url}\"")` 不行（MSVCRT 转义规则会破坏引号）。
- `keyring` 3.6.3 需要 `default-features = false, features = ["windows-native"]` 才是纯 Windows 后端（否则会拖进 secret-service 链）。
- 窄窗验收：用同源 iframe 量 `documentElement.scrollWidth` 也能取证，但要**说明与真实窗口的差别**（别把 iframe 结果说成"实机窄窗通过"）。
- git 不在 PowerShell PATH（用绝对路径或 Git Bash）。

## 8. 验收边界：没有凭据时，什么能验、什么必须挂账

**能验（且值得验）**：真库迁移（跑一次，比对新旧表行数 diff、扫 `%token%` 列名）、CLI 空态文案、fixture 浏览器走查、日志/输出泄漏扫描、协议向量的离线复算。

**不能验**：真实登录、真实发送、真实流水对照、平台侧限流行为。

**纪律**：不能验的一律写成"**挂账**"并写明恢复条件（需要什么凭据/注册什么回调地址），**不得写成已实测**；代码里的"成功路径"要有类似的诚实标注（例如常量块里写"成功路径一次都没跑过"）。
